# 루티즈 (Routiz) — 지도 기반 하루 코스 설계 프로토타입

기능명세서(2026-08-20)와 로우파이 시안을 기준으로 만든 **모바일 웹앱 형태의 동작 프로토타입**입니다.
장소 검색 → 코스 편집 → 순서·동선 확인 → 저장·공유 → 공개 코스 탐색·신고까지 실제로 눌러가며 확인할 수 있습니다.

## 실행

```bash
npm install
cp .env.example .env.local   # Supabase URL·anon key 채우기 (supabase/README.md 참고)
npm run dev      # http://localhost:5173
npm run build    # 정적 배포용 번들 (dist/)
```

`.env.local`을 채우지 않으면 회원가입·로그인·DB 저장이 꺼진 오프라인 모드로 뜹니다 (공개 코스·저장 장소가 비어있는 채로 화면 구조만 확인 가능).

데스크톱 브라우저에서는 가운데 폰 프레임으로, 모바일에서는 전체 화면으로 표시됩니다.
개발자도구의 모바일 뷰(390×844)로 보면 시안과 가장 가깝습니다.

## 디자인

무채색 기본 팔레트입니다. 키컬러는 검정(`#111111`)이고, 배경은 항상 흰색, 카드·구획 테두리는 진한 회색(`#4d4d4d`)을 씁니다.

- **색**: canvas `#ffffff` · ink/key(텍스트·브랜드) `#111111` · foreground `#333333` · muted `#888888` · surface `#eeeeee` · border(카드 등 테두리) `#4d4d4d`
- **라운드**: 12(버튼) · 10(카드·배지) · 18(검색) · 24(시트·작은 버튼) · 30(필터 칩) · 999(핀·토글)
- **간격**: 4 / 6 / 8 / 16 / 20
- **타이포**: SUIT. 화면 타이틀 28/700, 앱바 17/700, 본문 14/400(21px), 읽기 본문 14/400(24.92px, -0.2px), 캡션 12/400(18px, -0.2px)
- **컴포넌트**: 필터 칩(surface·30px), 배지(10px), 검색 컨트롤(18px·44px), 하단 탭은 화면에 고정된 일반 탭바(플로팅 아님). 그림자 토큰은 쓰지 않고 border로만 층을 구분합니다.
- **아이콘 없음**: 모든 동작은 텍스트 레이블로 표시합니다. 지도 컨트롤(확대·축소는 `+`/`-`, 전체 보기만 지구본 아이콘), 상태 표시 등은 대부분 글자입니다.

폰트는 jsDelivr의 SUIT를 `@font-face`로 불러옵니다(`src/styles.css` 상단). CDN을 차단한 환경에서는 시스템 산세리프로 대체됩니다.

## 구현 범위와 대체 구현

프로토타입이므로 서버 없이 브라우저 안에서 동작합니다. 지도만 네이버 클라우드플랫폼(NCP) Dynamic Map을 실제로 불러옵니다.

- **지도**: 네이버 지도(NCP Maps) Dynamic Map SDK를 `src/lib/naverMaps.ts`에서 동적으로 로드합니다. Client ID는 `.env.local`(`.env.example` 참고)의 `NAVER_MAP_CLIENT_ID`로 넣습니다 — 웹 서비스 URL 제한으로 보호되는 공개 식별자라 클라이언트 번들에 포함돼도 안전합니다. `VITE_` 접두사를 일부러 안 붙였습니다(Vercel이 `VITE_`로 시작하는 이름은 저장을 막는 경고를 띄우는 경우가 있어서요) — 대신 `vite.config.ts`의 `envPrefix`에 `NAVER_`도 등록해서 그대로 클라이언트에 노출되게 했습니다. 마커·경로선·구간 거리 라벨은 디자인 시스템 톤에 맞춘 커스텀 오버레이로 그립니다. NCP 콘솔의 **Web 서비스 URL**에 실행 도메인(예: `http://localhost:5173`, 배포 도메인)이 등록돼 있지 않으면 인증에 실패하며, `NAVER_MAP_CLIENT_ID`가 아예 없어도 마찬가지로 지도 대신 안내 배너가 표시됩니다. NCP 콘솔에서는 Dynamic Map·Geocoding·Directions가 Application 단위로 "이용 설정 상품"을 따로 체크해야 하는 별개 제품입니다 — `NAVER_MAP_CLIENT_ID`로 쓰는 Application에 **Dynamic Map과 Geocoding 둘 다** 켜져 있어야 지도와 주소 검색이 함께 동작합니다. Directions(경로찾기)는 REST 전용이라 별도로 Client Secret이 필요하고(아래 "경로·이동거리" 참고), 이 Secret은 **브라우저·Vercel에는 절대 넣지 않고** Supabase Edge Function 환경변수에만 둡니다.
- **경로·이동거리**: 기본은 하버사인 직선거리 근사이고, **자동차 구간만** 실제 도로 기준 거리·시간(NCP Directions 5)을 씁니다. Directions는 REST 전용이라 Client Secret이 꼭 필요해서, Supabase Edge Function(`supabase/functions/directions`)이 대신 호출하고 Secret은 그 함수의 서버 환경변수에만 둡니다 — 브라우저에는 절대 내려가지 않습니다. 화면은 렌더링 시점에 캐시를 먼저 확인해 직선거리 근사를 즉시 보여주고, 백그라운드로 실제 경로를 요청해 도착하면 자동으로 갱신합니다(`src/lib/directions.ts`). 도보/대중교통은 NCP Maps에 대응 API가 없어 항상 직선거리 근사를 씁니다. 여러 코스를 한 번에 보여주는 탐색·공개 코스 화면에서는 API 호출이 코스 수만큼 늘어나는 걸 막기 위해 실제 경로를 쓰지 않고, 내 코스를 직접 만들고 검토하는 화면(`#/`, `#/edit`, `#/order`, `#/summary`, `#/save`, `#/prefs`)에서만 씁니다. 도보 5km 초과 구간은 **경로 계산 불가**로 처리해 원인과 대안을 안내합니다.
- **장소 데이터**: 서울 주요 지역 40곳을 좌표·카테고리·영업시간과 함께 내장했습니다.
- **상호명·주소 검색**: `#/search`에서 검색어를 입력하면 내장 40곳과 동시에 두 API를 함께 호출해 "실제 장소·주소 검색 결과" 섹션에 보여줍니다.
  - **상호명 검색**("스타벅스 강남점"처럼 이름으로): NCP가 아니라 **Naver Developers**(developers.naver.com)의 지역 검색 API를 씁니다. REST 전용이라 Client Secret이 필요해 Supabase Edge Function(`supabase/functions/local-search`)이 대신 호출합니다(`src/lib/localSearch.ts`). NCP Maps와는 완전히 별개의 계정·자격증명입니다.
  - **주소 검색**(지번·도로명 주소를 그대로 입력했을 때): 네이버 지도 지오코딩(`submodules=geocoder`, `src/lib/geocode.ts`)으로 클라이언트에서 바로 찾습니다. 지도와 같은 Client ID·도메인 인증만으로 동작해 Client Secret이 필요 없습니다.
  - 두 결과는 좌표가 거의 같으면(약 11m 이내) 중복으로 보고 상호명 검색 쪽을 우선해 하나로 합칩니다.
  - 찾은 장소는 내장 장소와 동일하게 코스에 추가하거나 저장 장소에 담을 수 있고, 코스 저장·저장 장소 담기 시점에 `places` 테이블에 자동으로 등록됩니다(상호명 검색은 카테고리를 업종 키워드로 추정하고, 추정 실패 시·주소 검색은 카테고리를 "기타"로 둡니다). id를 좌표 기반(`p-geo-{lat}-{lng}`)으로 만들어 같은 곳을 다시 찾아도 중복 등록되지 않습니다.
- **이미지 인식**: 캡처 이미지 업로드는 OCR을 흉내 내 후보를 반환하고, 텍스트 붙여넣기는 실제로 파싱해 내장 장소와 유사도(dice 계수)로 매칭합니다. 매칭이 불확실하면 직접 연결·제외할 수 있습니다.
- **인증·회원가입**: Supabase Auth 이메일/비밀번호 회원가입·로그인입니다(카카오·구글 없음). 회원가입 시 닉네임·연령대·유입 경로·기대 기능(복수 선택)을 받고, 프로필 이미지는 선택 사항입니다. `.env.local`(`.env.example` 참고)에 `VITE_SUPABASE_URL`/`VITE_SUPABASE_ANON_KEY`가 없으면 회원가입·로그인이 비활성화됩니다.
- **온보딩**: 회원가입 후 선호 조건(`preferences`)을 한 번도 저장한 적 없는 계정은 자동으로 `#/onboarding`으로 이동해 이동수단·선호 장소 유형을 고르고("건너뛰기" 가능), 그 순간 DB에 선호 조건 행이 생기면서 다시 뜨지 않습니다.
- **권한**: `profiles.role`이 `user`/`admin`으로 나뉩니다. 관리자만 `#/me`에 뜨는 "관리자 대시보드" 버튼으로 가입자 수·요약 통계·전체 비공개 코스를 볼 수 있고, 통계는 서버(RPC)에서 관리자 여부를 확인하므로 일반 사용자는 API를 직접 두드려도 볼 수 없습니다.
- **저장소**: 실제 저장 데이터는 Supabase Postgres(`supabase/schema.sql`, RLS 포함)와 프로필 이미지용 Storage 버킷에 저장됩니다. 아직 "코스 저장"을 누르지 않은 편집 중인 초안만 로그인 여부와 상관없이 브라우저 `localStorage`에 남아 있다가, 저장하는 순간 로그인한 계정 명의로 DB에 올라갑니다. 자세한 내용은 `supabase/README.md` 참고.
